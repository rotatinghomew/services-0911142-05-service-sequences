# 现场复核

先在画外完成依赖或镜像准备。服务就绪检查为 `/health`，启动不下载资料。打开首页，选择登记月份，查看按户排列的服务接触历程；从任一明细点开原始记录核对。保存一次当前材料，然后改动选择并重新计算，再打开刚才的记录，确认原范围仍在，最后导出。

上述操作的设计时长为45至75秒，留出异常提示时间后不超过90秒。部署故障不隐藏也不回放旧结果。

## 分型复核流程

1. 在“历程分型”区选择数据版本并训练（默认 40 次固定种子自助，约数秒至十几秒）。先读类数选择表：轮廓系数与自助 ARI、共分配率、最小类规模同时呈现，推荐 k 只从稳定候选中产生；不稳定候选保留在表中而不是被隐藏。
2. 打开稳定性报告，核对窗长截断检验：早期户截断到晚期观察窗后 ARI 接近 1 且无移动户，表示现有差异不是窗长造成；出现移动户时逐户查看其截断后剩余事件数，再判断是否为真实路径变化。
3. 逐类阅读 medoid 代表路径与组内差异（事件数、观察窗、间隔、渠道、先验使用、覆盖缺口、重复上报），在命名框填写接访员可用的名称并保存为命名版本；改名只追加新版本，历史可在“命名版本历史”中回看。
4. 接访时在“新记录接访归类”区上传待归类完整资料并填写户标识。结果为“不适合归类”时不得硬派：阅读拒识原因（距离超 95 分位或类间边际不足）与相似户距离分解，转人工接访。
5. 新数据到来后重新训练会得到新的分型版本，旧版本及其人工名称保持不变；类别名称不会因为重新学习而被默默重排。

新增分析的实际结果和可操作性须在功能完成后重新验证；这里不预报尚未开发能力的演示结果，不限定显著性或结论方向。
